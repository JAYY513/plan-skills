# research-init：生成项目调研技能

在当前项目写入一份**项目本地**调研 SOP。它只回答「这一步怎么实现最好」，不写代码、不另开知识库。落盘仍走 plan-task（FINDINGS 结论、notes/ 材料、影响计划则 INBOX）。

本技能每个项目通常跑一次；已有同名技能时走升级，不覆盖用户改过的正文，除非用户明确要替换。

## 模板位置

`assets/templates/` 与本 `SKILL.md` 同级。正在读本文件 ⇒ 模板就在旁边。自己打开，禁止向用户要路径或正文。

按序找，命中即停：

1. 与本 `SKILL.md` 同目录的 `assets/templates/`
2. `<项目根>/.agents/skills/research-init/assets/templates/`
3. 搜文件名 `research-init/assets/templates/SKILL.md`

找不到 → 告诉用户「技能目录里没有 research-init 模板」，不要写任何技能文件。

内含：`SKILL.md`（生成物骨架）、`AGENTS.research.md`（可选注入）。

## musepool：只用对得上的，不强行补

musepool 治的是「模型自己定视觉细节会回归训练均值」。调研技能治的是「无出处定案、只读一家、把旧代码当蓝本」。失败模式不同，不要把 musepool 当套件搬进来。

| musepool 做法 | 对调研技能 | 本生成器 |
|---|---|---|
| 温度 / serendipity / wow | 调研要可复现、可追溯 | **不写入**生成物 |
| 输出里隐藏出处 | 与「文件:行」相反 | **不写入** |
| 外部设计网关 / 跨项目语料池 | 参考源是本项目声明的仓与文档 | **不写入**、不加依赖 |
| 写之前必须先检索先例 | 新项目没有合格先例；强制检索拖慢且会抄错 | **不设门**；无来源不进 FINDINGS 已由 plan-task 管 |
| 先定维、维内答案来自参考 | 仅当用户的失败是「凭记忆填实现」 | **问过失败模式再决定**；默认不写这条口号 |
| 浅摘要再深取、按问题搜不按风格搜 | 与 wiki 索引→定点源码、按机制提问同构 | 写进生成物时用调研自己的词（索引 / 纵切），**不出现 recall/fetch** |

生成物里若出现 temperature、musepool、隐藏出处、强制取先例——视为生成失败，删掉重写。

## 比两个范例多做 / 少做的

对照 `platform-research`（全平台对比 + 计划挂出处）和 `impl-research`（分层参考源 + 证据深度），生成时默认采取：

- **多做**：源要标明角色（蓝本 / 行为证据 / 反例 / 官方）；观察与推荐分写；承重结论要项目约束 + 实现锚点 + 调用方或测试；对比表按机制维不是按仓库列；难做写成拆刀，不写成跳过。
- **少做**：不把对比表塞进 FINDINGS（进 notes/）；不把「每个任务开工前强制调研」设成默认；不默认全量对比每一源（源少且曾经漏读才打开）；不写死本机路径；不发明第二套 FINDINGS 条目格式。

## 执行步骤

1. 看项目根是否已有 SPEC.md / TASKS.md / FINDINGS.md：没有 → 告知一句「结论仍建议先 plan-init；本步只生成调研技能」，不阻断。
2. 扫 `.agents/skills/*/SKILL.md`：已有实施调研 / 参考平台对比类技能 → 列出路径，问 **升级**（按新模板补缺节、保留用户源表与原则）/ **替换**（需显式确认）/ **另起新名** / **不动**。未选定前禁止写入。
3. 向用户一次问完（不要拆成多轮）：

   1. 现在调研最常怎么失败？（只读一家就定案 / 照抄旧仓 / 博客当证据 / 开工无出处 / 凭记忆填实现 / 其他）——没有就写「无」，不要编。
   2. 参考源有哪些？每源一行：名称、路径或 Wiki Sources 别名、角色（蓝本 / 行为证据 / 反例 / 官方）。没有源 → 停，不要生成「去网上随便搜」的技能。
   3. 哪些机制维真会翻车？（取消、状态机、许可证、协议…）没有把握 → 填「按任务临时定维」，不要凑满 8 条。
   4. 是否必须每个源都对比？（仅当源少、且曾经预设跳过某家才选是；默认否。）
   5. 是否作为「机制设计任务」的开工门？（默认否：用户点名或任务明确要「怎么实现最好」才跑；选是则只挡机制设计，不挡普通小任务。）
   6. 技能 kebab-case 名 + 触发词。无名默认：多源对比用 `platform-research`，实施步骤用 `impl-research`。

4. 用模板生成 `.agents/skills/<技能名>/SKILL.md`：结构用模板，源表/维度/开关用用户回答填充。源表行数等于用户声明的源，不要为凑 L1–L4 编层。用户没选的 HTML 注释块整段删掉。用户没说的原则不要写（例如没提兼容就不要写「不考虑兼容」）。
5. 若项目有 AGENTS.md：没有 `## 调研技能` 则把 `AGENTS.research.md` 填好技能名追加到末尾；已有则只改技能名/路径那一行。不要改 `## 计划纪律`。
6. 完成后用两三句告诉用户：何时会触发、已结算结论进 FINDINGS、对比表 / 待确认进该任务 notes/。

## 生成质量门

落盘前自查，任一失败则改模板输出，不要交给用户打磨：

- description 含能力句 + `Use when` 触发词；可被模型自动选中（不要 `disable-model-invocation`）。
- 有非目标：不写实现、不改 SPEC/ROADMAP、落盘走 plan-task。
- 参考源表每行有角色；无「通读全仓」。
- 承重 / 普通 / 冲突的证据深度写清；缺锚点只能标待确认并留 notes，不能当推荐、不能以有效进 FINDINGS。
- FINDINGS 只要求一段话已结算结论 + 关键出处；对比表、证据账本、出处清单、待确认在 notes/。
- 全文无 musepool 网关、温度、隐藏出处、强制先例门。
- 「先定维再填答案」仅当步骤 3.1 的失败含「凭记忆填实现」才出现。

## 原则

- 调研技能是项目 SOP，不是通用搜索引擎。
- 参考源由用户声明；生成器不发明源、不联网配语料。
- 与 plan-task 分工：本技能生成「怎么查」；plan-task 管「查完写哪」。
