## 总体结论

文档平均 **3.1 / 5**（需补，未达「定稿待施工」）。痛点证据（§1）和四步施工（§10）是最强两节；核心契约 §5 只有 **2.9**，带着未冻结的命令面进施工会返工。

剩余短板三类：

- **P0 阻断**：命令枚举自相矛盾；`--impact` / `--source` / `ws --position` 无模型或无契约；引擎写入例外与原则 3 冲突；INBOX 了结方式与现 SKILL「移入已裁决」替换而非 additive；心跳文案 §3≠§11。
- **P1 落地**：状态变化检测字段未冻；标题相似算法未定义；命令失败/未找到/歧义无退出码；L0–L3 与命令表错位。
- **P2 运营**：行数对比无采集方法；观察期两周无记录位置；现网 `status --json` 去留未决。

建议：先改 §5+§6+§4 原则正交，再开工 §10 步 1。不要按当前「定稿」直接切 `plan.mjs`。

## 建议改写顺序

### P0：阻断

1. **重写 §5 命令面**：一张表列出全部命令（建议 8 查询 + `reindex` + 现有 `start/finish/doctor`），每行：argv、默认输出、`--full` 语义、退出码（0 命中 / 1 无体系 / 2 未找到 / 3 解析残缺）。落点：§5 全节；删「10 个」「2 新增 + 3 扩展」。
2. **补数据字段，删空滤参**：§6.1 把模板已有的 `- 来源：` / `- 影响：` 标为查询维（可缺 = 不参与过滤）；索引列是否含来源/影响写死一列。`--status` 枚举抄模板原文。落点：§6.1、§5 findings 行。
3. **冻结 CLI 与 hook 同一入口**：要么 §5 增加 `ws --position`（= 无 `--full` 的默认三行），要么 §3/§8 改成 `ws <slug>`。禁止案例调用未列 flag。
4. **改原则 3**：引擎可写集合显式列为 `{finish 四动作, reindex 索引, （是否含 start：建议删 start 再生）}`。原则 1 加例外：无 node → 读受管索引区/当前位置区；无过滤且文件 <N 行 → 允许整读。落点：§4、§6.1 再生时机、§8 兜底。
5. **INBOX 单一了结**：二选一写进 §6.3 + 迁移句——(A) 保留「已裁决」区，引擎 `finish` 移区（兼容现 SKILL）；(B) 行内 `- 已解决：`，引擎双读旧区作已解决，plan-init 改模板。`doctor` 对缺 `plan-index` 标记 = WARN 不是 FAIL。
6. **心跳一行定稿**：采用 §11 指针句，回写 §3 ③；§8 写比较集（建议：进行中标题集合 + 队首标题 + INBOX 未决计数，不含 DoD 正文，避免再走 1.1 的原文节流）。
7. **`--json` 裁决**：保留现有 `status --json`（已实现、测试可能依赖），§2/§9 改为「新查询命令不做 `--json`，`status --json` 维持」。或真删则写入 §10 步 1 与测试改动。
8. **验收条 4 改成可测蕴含**：有 `- 来自：` 或 `--resolve` → 写已解决；否则 → 一行软警告且不写。与 §3 ⑦、§9 软警告一致。

### P1：落地摩擦

1. §7.2 相似算法：归一化规则（去书名号/空白/大小写）、中文按字还是按空白 token、60% 分母（较短标题长度）。给 2 条正例 + 2 条反例。
2. §5 每个只读命令补失败输出金句：`task` 重名、`findings --full F99` 不存在、`inbox` 文件缺省。
3. 分级表重画：L0=findings/inbox/links 索引行；底线=`status`（session-start）；L1=next/task/ws；`context` 降级为 SKILL 组合拳（`status` + `findings --tag`）或删命令（它违反原则 5）。
4. §10 每步「可停」补：回滚后 CLI 行为、是否留下 `plan-index` 标记、hook 是否仍旧注入原文。
5. 现 `finish --date` 写回 §5，避免施工丢掉已有 argv。

### P2：迁移与运营

1. §12 行数验收写测量方法：对 fixture 跑 hook，断言 stdout 行数，而不是「模拟会话符合 §3」。
2. §11 观察期：两周日志落哪（FINDINGS 还是 notes）、什么信号判定「弱模型不跑命令」。
3. §0 压成文首 3 条 bullet，避免独立成章拉低可读性以外的维度。
